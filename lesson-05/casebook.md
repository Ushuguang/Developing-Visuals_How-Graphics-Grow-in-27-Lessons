# 第五章案例讲解手册

配合本章“讲解 / 关键代码 / → 映射 / 演示”使用。每节先提出一个可观察的问题，再进入映射逐步验证。原讲义和原案例继续保留，本手册补充课堂讲法，不替换教材中的知识点。

## 5.1 一份校园日程，五种时间视角

**案例是构造的**：以08:00早餐、09:00上课、12:00午餐、18:00运动的日程为主线，配合温度采样、双地点记录和全年日历。排序演示保持四件事不变；其余属性分别使用明确标注的补充微例。

1. **有序**：先按读入顺序18:00、08:00、09:00、12:00摆放，再按时间排序。沿连线追踪同一个事件，说明重排不改记录；先发生不自动等于因果。
2. **连续**：构造两个教室温度采样点09:00:00的21°C和09:01:00的23°C。可以定位09:00:30，继续细分间隔；中间温度没有测量，不能把连线当成实测。
3. **周期**：明确假设日程每24小时重复。第1天与第2天09:00相距一天，取模后的相位相同。修改上课时刻，观察两天一起转动。
4. **独立于空间**：图书馆与操场都发生09:00事件；时间视图可共享同一位置，加入地点编码才分得开。地点不是由时间值推算的。
5. **结构**：切换2023/2024，观察年→月份→日数，比较2月28/29天。左侧原代码的2024范围包含366个日期，结束日期2025-01-01不在范围内；2023是补充对照输入。

**板书顺序**：记录 → 时间属性 → 选择表达形式。左侧第一段是属性配置，右侧微案例是对属性的补充图解，不声称原配置代码本身画出了所有图形。

## 5.2 人名流行的接力

**保留原JSON**：Marie、Jean、Camille，1900–2020，每条121个记录。文件原始出处和统计单位尚待教师确认，结论只限文件中的值，不据此虚构社会原因。

**先问**：同一年谁的值更高？若只看1950–2000，是否仍能公平比较三条线？

1. 年份解析：数字/字符串年份进入`timeParse`，得到本地Date；这一步不画曲线。
2. 时间映射：Date进入同一个`scaleTime`，读出真实x坐标；这一步还没有频率线。
3. 三线追踪：加入三条曲线、频率轴、同年追踪点与读数表。默认1965年的原值是4711、4394、399。
4. 共同窗口：显示全程概览和窗口框；1950–2000三条线一起裁为51点，1980–2020为41点，原值不改。

**继续探究**：点击文件内峰值定位；选择另一个年份，比较原值差。提醒学生“窗口看起来更陡”可能来自时间轴范围变化；点数本身不能单独决定合适的插值方式。

## 5.3 给闰日找座位

**保留原天气CSV**：跟踪2024-02-29。文件中当天最高温记录为1°C；来源尚待教师确认。不要把缺失当0°C，也不要把天气季节性当作周内周期的证据。

1. 全年日期：先看366天有序序列，闰日是第60天。
2. 星期行：按星期分成七桶，找到周四；此时还没有周列和温度色。
3. 周列：按实际周边界分桶，明确周日/周一起点的区别。原讲义简化`floor(dayIndex/7)`保留对照，不默认它与正确周列相同。
4. 格点：用行、列交叉定位唯一日期，只画中性色；读取当前格宽、边距和视野偏移后的实际SVG坐标。
5. 色值：同一格点加入温度颜色和色标指针。切换colormap时日期、数值和位置不变。
6. 月界：在同一热图上叠加月份边界，核对七天前与今天的年月。

**继续探究**：查看元旦、闰日、年末与跨周快捷点；在源文件里定位最高/最低温。展开同一份温度的折线概览，比较“趋势”和“日历位置”这两种阅读任务，不添加未经数据支持的节假日效应。

## 5.4 从一个点到闭合扇环

分清两个问题：**如何生成原运行几何**，以及**怎样安排周期相位**。原运行图采用近似等弧长采样，不自动保证一圈等于一年、一月或一周。

1. 半径：固定一个原日期，读真实θ与r，显示圆心、半径和起点。
2. 投影：把同一点分解为x/y，两条投影与读数一一对应。
3. 角增量：比较首、当前、末日期的实际r、Δθ和近似弧长。选中首/末日期时去掉重复项。半径变大时Δθ需要变化，不能用固定角增量冒充原算法。
4. 四顶点：分别选中外起点、外终点、内终点、内起点，核对坐标。切换“讲义公式L四边形 / 原运行A圆弧”时明确使用的参数。
5. 路径：依次点击M、L₁、L₂、L₃、Z，只有Z闭合后填色。切到原运行模式则是M、A₁、L、A₂、Z。虚线是定位参考，不是已经执行的路径。

**补充微案例**：构造两周学习活跃度`[2,3,6,5,4,8,1]`重复，两个布局使用完全相同的14条ID/值。周相位布局能让相隔7天的位置同相位；等弧长布局不自动满足这一点。该案例不是天气，不修改原CSV。

**几何提醒**：若`r=bθ`，转一圈的半径增量是`2πb`。本课原讲义部分参数、路径和运行图不同，不能把两组顶点说成完全一致。

## 5.5 角色线为什么聚在一起

默认保留《侏罗纪公园》五角色、27个控制点、两事件。原轨迹是课堂叙事示意，个别坐标和讲义叙述存在差异；不新增未提供的角色，也不编造缺失时刻的样本。

**更直观的构造案例**：切换“校园小组协作”。三位同学在六个时刻经历分工→会合→再分工；15分钟时三条线被手工安排靠近。y表示协作情境布局，不是人数或真实地理距离。

1. 时间：先画每人的时间轨道，同刻参考线共用x。
2. 控制点：选一位同学，看原`{time,y}`与实际像素坐标；点图元可反选此步。
3. 整组绑定：一个人的数组通过`datum(c.points)`绑定一条path，观察数组框与单一路径。
4. 曲线：同一组点同时显示线性骨架与Catmull-Rom。改变alpha，曲线路径改变，原点与骨架不改。
5. 事件：出现独立事件圈、文字和时间垂线；只对真实存在的同刻控制点画实点，缺失的仍显示无该刻控制点。

**提问**：一条角色线和一个事件为什么应共享时间x，却不必共享y？学生应能从表格中指出证据。

## 教师核对依据与边界

- [D3时间区间](https://d3js.org/d3-time#interval_range)：范围包含起点，排除终点；本地日不应简单当作固定毫秒数处理。
- [D3时间尺度](https://d3js.org/d3-scale/time)：本课用Date域与像素范围解释时间映射。
- [D3曲线文档](https://d3js.org/d3-shape/curve#curveCatmullRom_alpha)：Catmull-Rom的alpha是参数化选择，不能直接等同Cardinal的tension。原讲义措辞待教师核对，本轮不静默改写原文。

新增案例旨在把计算过程变得可观察；尚未通过真实学生实验验证学习效果。
